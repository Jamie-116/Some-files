## 规则 0：Mode + Visual-Style 双轴体系（v2.10.0+）

v2.10.0 将 PPT 的**结构**和**外观**解耦为两个正交维度，Strategist 独立锁定：

### Mode（论证结构）— 决定"怎么讲"
| Mode | 适用场景 |
|------|---------|
| `pyramid` | 金字塔原理，结论先行 → 分论点 → 论据（咨询报告、战略汇报） |
| `narrative` | 叙事弧线，起承转合 → 高潮 → 结论（品牌故事、案例分享） |
| `instructional` | 教学递进，概念 → 原理 → 实操 → 总结（培训材料、产品手册） |
| `showcase` | 展示冲击，视觉主导 + 最少文字（发布会、TED 风格、Keynote） |
| `briefing` | 简报速览，要点列表 + 数据支撑（周报、月报、快速同步） |
| 自定义 | 用户可指定任意论证结构 |

### Visual Style（视觉风格）— 决定"长什么样"
v2.11.0 提供 **18 种**命名风格（对应 `references/visual-styles/*.md`），按家族分组：

| 家族 | Visual Style | 特征 |
|------|-------------|------|
| 极简专业 | `swiss-minimal` | 网格系统、大量留白、无衬线字体、克制用色 |
| 编辑排版 | `editorial` | 杂志感、大字标题、摄影图片、栏式排版 |
| 柔和亲和 | `soft-rounded` | 大圆角、柔阴影、温暖色系、亲和力强 |
| 科技深色 | `dark-tech` | 深色底、霓虹色强调、科技感线条、发光效果 |
| 粗野主义 | `brutalist` | 极粗字体、高对比、无圆角、原始感 |
| 蓝图工程 | `blueprint` | 蓝色网格底、工程标注线、技术图纸风格 |
| 孟菲斯 | `memphis` | 几何图案、大胆配色、波普艺术感 |
| 拼贴志 | `zine` | 拼贴感、手写字体、不规则布局 |
| 摄影社论 | `photo-editorial` | 全幅摄影底图 + 文字叠加 |
| 数据新闻 | `data-journalism` | 数据可视化主导、图表密集、信息图风格 |
| 水墨 | `ink-wash` | 中国传统水墨、留白意境、毛笔笔触 |
| 玻璃态 | `glassmorphism` | 毛玻璃效果、半透明层叠、弥散阴影 |
| 黑板 | `chalkboard` | 黑板/绿板粉笔字效果，手写感 |
| 墨水笔记 | `ink-notes` | 钢笔/圆珠笔手写笔记风格 |
| 纸雕 | `paper-cut` | 剪纸/纸雕层叠效果，投影深度 |
| 像素艺术 | `pixel-art` | 像素化/8-bit 游戏风格 |
| 速写笔记 | `sketch-notes` | 铅笔/炭笔速写风，不规则路径 |
| 复古海报 | `vintage-poster` | 复古印刷/海报风格，做旧纹理 |

### 与规则 2 布局模式 A-F 的关系

```
Visual Style（规则 0）    →  全 Deck 统一，决定"长什么样"
Mode（规则 0）            →  全 Deck 统一，决定"怎么讲"
布局模式 A-F（规则 2）    →  逐页选择，决定"这一页怎么排"
```

**三者正交**：任意 Mode × 任意 Visual Style × 任意布局模式 A-F 均可组合。例如：
- `pyramid × Swiss-minimal × 模式 D 架构页` = 咨询风的四层架构图
- `showcase × dark-tech × 模式 B 痛点页` = 科技感发布会痛点分析
- `instructional × soft-rounded × 模式 C 递进页` = 亲和力培训材料

### Strategist 锁定流程（v2.11.0 更新）
1. Strategist 分析源文档 → 独立锁定 `mode` 和 `visual_style`
2. v2.11.0 Step 4 八项确认已升级为**交互式可视化确认页面**，包含：
   - 颜色 + 排版实时预览（CJK/Latin 独立）
   - 自定义 HEX 颜色输入 + 实时色板
   - Visual Style 展现为**个性光谱**（≥3 候选：safe → shifted → bold）
   - 确认的 `result.json` 权威高于 AI 推荐
3. 确认后的 `spec_lock.md` 同时包含 `mode` 和 `visual_style`

## 规则 1：排版密度硬规则（排版宪法）

**核心**：严格平衡高信息密度与精细化排版，既不文字塞满拥挤，也不空白浪费版面。

### 空间利用率
- 内容区域覆盖页面面积的 75%–90%（1280×720px）
- 页面四边留白 24–48px，非装饰性空白不得连续超过 120px
- 页面底部禁止出现 ≥80px 高度的连片无意义空白区

### 元素间距
- 卡片间距 12–16px，模块间距 20–32px
- 标题与内容间距 ≤24px，同组元素间距 ≤16px
- 禁止为了"看起来干净"而放大间距导致内容区缩水

### 内容区内空白管控（反内部空洞）
页面四边不留白不等于内容区内部就可以浪费——正文中间同样禁止大面积无意义留白。

- **列间空白**：双栏/三栏布局中，栏间距 ≤40px。禁止因栏宽不足导致栏间出现 ≥60px 的连续垂直空白走廊
- **卡片内部**：卡片内文字/图标/色条应充分利用卡片空间，卡片内连续空白区 ≥ 卡片面积的 35% → 缩小卡片或增加内容层级（如补充标签行/指标数值）
- **行间空白**：上下两个内容组之间的垂直间距 ≤ 组内元素间距 × 2。禁止出现 ≥100px 的连续水平空白带横贯页面
- **四周 snug 但中间空**：页面四周留白合规，但中心区出现 ≥ 页面面积 20% 的连续空白 → 同样视为不达标。补齐方式同"内容偏少时的补齐策略"
- **自检方法**：生成后扫描页面，将红框内空白区域（非页面边距、非元素间合理呼吸间距）的高亮出来；若任一空白块 ≥ 150×100px 且无信息量 → 必须填补

### 内容偏少时的补齐策略（反空白）
按优先级依次：① 增加同风格轻量化设计元素（小型图标色条卡片、标签组、数据指标胶囊）→ ② 扩展已有元素的细节层级（副标题行、补充标签、量化指标）→ ③ 添加底部装饰条/侧边细线/角标元素

**禁止**：为填空白而重复已有内容、放大字号、或添加无信息量的纯装饰色块。

### 内容过多时的压缩策略（反拥挤）
① 先精简文字（`·` 分词替代完整句子，削减修饰性定语）→ ② 再压缩间距至下限值 → ③ 仍放不下则拆页

**禁止**：字号 <11px 或行距 <1.2。

## 规则 2：页面设计风格模式库

每次生成内容页时，先判断逻辑类型，选对应布局模式。

### 模式 A：转型对比页
左栏（~40%）图标色条要点卡片 + 右栏（~60%）"传统 → AI赋能 → 新范式"对比框 + 底部升级指示条。适用：趋势洞察、行业背景、能力跃迁。

### 模式 B：痛点-桥梁-解决页
顶部对比图 → 中部三栏（痛点红底 → 动作词 → 解法蓝底）→ 底部虚线框"缺了什么？"→ 答案蓝条 → 四路径底栏。适用：痛点分析、必要性论证。

### 模式 C：层级递进页
左栏（~65%）等宽水平层卡片 + 右栏（~30%）逐级说明图。每层：编号图标 + 标题 + 1行描述 + 标签。适用：建设逻辑、架构分层、阶段规划。

### 模式 D：系统架构页（2026-06-11 参照 changan-gas P06 修正）

**参照 SVG**：[`layout-ref-architecture-layered.svg`](layout-ref-architecture-layered.svg) —— 长安天然气项目 P06，经过实际验收的成熟布局。**生成前先读此文件，套用其结构，只替换内容数据。**

**参照实现**：`changan-gas-platform/svg_output/06_architecture.svg` + `delian-yitihua-platform/svg_output/09_architecture.svg`

**强制规范（已验证可用）**：
- **层标签**：左侧 **36px 宽圆角色块**（rx=8），内写大号数字（01-04, 22px bold 白色），**不写文字**。文字标签太挤且不美观
- **层容器**：**虚线边框** `stroke-dasharray="6 4"` + **浅色底色**（fill-opacity 0.3±），层名在容器**内部左上角** 12px bold
- **容器宽度**：1112px（从 x=108 到 x=1220），充分利用画布
- **卡片规格**：统一 68px 高，白色底 rx=8，左侧 32×32 rx=8 浅色方块 + 单汉字（16px bold）+ 右侧 15px bold 标题 + 12px 描述。每层卡片数量灵活（2-5 个），等宽分布
- **设备层**：用小 tag pill（130×28 rx=6, stroke=#E2E8F0）替代大卡片。设备名短用独立 pill，长用合并 pill
- **保障体系**：底部横向双色条（36px 编号色块 + 虚线容器），文字横排。**严禁 rotate(-90) 旋转文字**
- **顶部**：4px 全幅蓝色条 `#0082FF`，标题左对齐
- **层色映射**（自下而上）：L1=灰 #94A3B8 / #F8FAFC、L2=青 #28E6E6 / #ECFDF5、L3=紫 #8254F0 / #F5F3FF、L4=蓝 #0082FF / #EFF6FF

**反模式**：
- 层标签用 60px 宽色块塞 4-5 个汉字 ❌
- 设备层用大卡片挤成一团 ❌
- 右侧竖排 `rotate(-90)` 文字 ❌（违反 [[ppt-svg-hard-rules]] S5）
- 从零发明布局而不参照已验证的成熟页面 ❌

### 模式 E：分组列表 + 交互图
左栏（~35%）功能条目按色条标签分组 + 右栏（~65%）交互示意图 + 底部核心能力卡片。

### 模式 F：流水线 + 功能卡片
顶部 5 节点流水线箭头链 + 主体 2列N行功能卡片 + 底部闭环说明。

## 规则 3：通用视觉规范（跨模式）

以下规范适用于所有布局模式（A–F），也适用于模式库未覆盖的自由排版页面。

- **图标色条卡片**：左侧 6-8px 色条 + 28-56px 圆角色块（1个粗体汉字）+ 标题(15-20px) + 正文(≤3行, 13-14px)
- **架构层卡片（changan P06 验证）**：白色底 rx=8, stroke=#E2E8F0，左侧 32×32 rx=8 浅色方块内 1 个 16px bold 汉字，右侧 15px bold 标题 + 12px 描述。卡片等宽，gap=12-14px。**此模式高度可复用，优先套用而非从零设计**

- **编号卡片（财会 P06 验证）**：参照 [`layout-ref-card-layered-with-number.svg`](layout-ref-card-layered-with-number.svg)，**层叠架构页的首选卡片模板**。核心要素：
  - 层容器：820×100 rx=10，左侧 6px 色条 rx=3 + 浅色底色 + 1px 同色系描边
  - 编号方块：44×44 rx=10，Georgia serif 20px bold，同色系浅底
  - 三行文字：标题 18px bold + 描述 14px #595757 + **【标签】12px bold**（前缀用【核心痛点】【数智成效】【关键突破】等，颜色与层级对应）
  - 右侧面板：298px rx=12 #F5F8FC，内含 rx=8 子卡片
  - 底部结论条：全宽 80px rx=8，蓝色底 + 白色大字结论（18px bold）
- **配色约定**：传统/痛点→浅红底 #FFF5F5 + 红色 #FF6B6B；新范式/解法→浅蓝底 #F0F7FF + 蓝色 #0082FF；过渡/桥梁→紫色 #8254F0；辅助→青色 #28E6E6
- **叙事结构**：必须有清晰视觉流（问题 → 中间态 → 答案 → 路径），拒绝扁平罗列
- **文字密度底线**：每页正文 ≤250 字（不含标题和页脚），单卡片正文 ≤3 行每行 ≤30 字，能用 `·` 分词就不用完整句子

## 规则 4：TOC 目录三行信息层级

TOC 页必须采用三行独立 `<text>` 设计，拒绝单行扁平列表。

| 元素 | 字号 | 颜色 | x | y |
|------|------|------|---|---|
| 编号 | 22px bold | #0082FF | 500 | 基准 y |
| 标题 | 22px | #2E2E32 | 544 | 同编号 y |
| 副标题 | 14px | #595757 | 544 | 标题 y + 30 |

- 章间距：~80px（y 依次递增 80）
- 左侧边栏保留：目录标题 40px 白色 bold + 分割线 + 英文副标题 20px 白色
- 不使用多余装饰元素（圆点、线条）

## 规则 5：KPI Hero Number 溢出防护

大字体数字的视觉边界必须在卡片内部，不与上下元素重叠。

**计算公式**（实际渲染高度 ≈ 字号 × 0.75~0.8）：
```
数字视觉顶部 ≈ baseline_y - font_size × 0.8
数字视觉底部 ≈ baseline_y + font_size × 0.2
卡片上沿 ≤ 数字视觉顶部 - 10（至少 10px 呼吸空间）
标题视觉顶部 ≥ 数字视觉底部 + 14（至少 14px 间距）
```

**核心原则**：Hero Number 字号 ≤ 卡片高度的 30%。设计前先累加所需高度（色条 + 数字 + 标题 + N行描述 + 标签），确保总需求 ≤ 卡片高度 - 上下各 15px 留白。

## 规则 6：page_layouts 克制 + 底部闭合 + 视觉隐喻密度

2026-06-11 新增。基于「陕西德联一体化平台」vs「长安天然气一体化平台」的横向对比分析得出，针对 AI 生成 PPT 的三个系统性薄弱点。

### 6a. page_layouts 克制原则（反千篇一律）

**教训**：德联项目的 spec_lock 中 page_layouts 将 20 个页面全部标记为模板继承（包括全部内容页绑定 `03b_content_two_col`），导致全篇左右分栏布局高度雷同。长安天然气项目只标记了 6 个结构性页面，内容页自由设计，视觉多样性显著更高。

**2026-06-11 二次修正**：从"全部继承"矫枉过正到了"全部不继承"，导致内容页完全裸白底、无 Logo、无模板标题栏。正确做法是**框架继承 + 内容自由**。

**强制规则**：
- `spec_lock.md` 的 `page_layouts` **结构性页面必须标记**：封面(Cover)、目录(TOC)、章节过渡(Chapter)、结尾(Ending)
- **正文内容页：标记模板头部框架**，Agent 继承以下元素后内容区自由设计：
  1. 模板 Logo（image6.png / image3.png，位置和尺寸照搬模板 SVG）
  2. 标题栏结构（标题字号、颜色、位置参照模板）
  3. 整体背景（内容页用模板的 image7.jpeg / image8.jpeg 做全幅底图，或纯白底）
- **禁止**将完整的 `03a_content_full` / `03b_content_two_col` 整页继承（那会锁死双栏布局），但**必须**从中提取头部框架（Logo + 标题栏）
- Agent prompt 中必须明确列出 Logo 文件和坐标

### 6b. 底部闭合条（反底部空白 + 信息闭环）

**教训**：长安天然气几乎每页都有底部总结条（insight bar），德联部分页面底部留白偏大且无视觉收束。

**强制规则**：
- 每个正文页底部必须有一个轻量闭合元素
- 高度 30–55px，浅主色底（如 `#F0F7FF`）
- 内容为：数据标签 / 总结短句 / 关键结论 / 来源标注 / 硬件需求提示
- 作用：视觉闭合 + 信息补强 + 消除 ≥80px 底部空白

### 6c. 视觉隐喻密度（反纯卡片平铺）

**教训**：德联大量页面为文字卡片罗列。长安天然气 P04 使用了"平台名称词云 → 漏斗汇聚 → 统一方案卡片"的视觉叙事链，信息传达效率显著更高。charts_index.json 包含 71 个模板，德联只用了 2 个，长安天然气用了 5 个。

**强制规则**：
- 每个章节至少保证 1 页使用图表化隐喻元素：汇聚漏斗 / 金字塔 / 中心辐射 / 流程箭头链 / 对比天平 / 环形循环
- 优先从 `charts_index.json` 的 71 个模板中选取（含结构型模板，非仅数据图表）
- 每份 PPT ≥4 个不同 chart template（当前实际：长安天然气 5 个，德联 2 个）
- Strategist 在 §VII Visualization Reference List 中必须列出至少 4 个匹配

### 6e. 禁止自动添加来源行（2026-06-25 新增）

**教训**：data-journalism 风格的"mono 来源行"是风格特征，但除非用户明确要求，不应自动添加到 PPT 中。融通项目 v2 自动添加了"来源：项目可研报告 · 2026.06"到全部 14 个内容页，用户反馈不需要。

**强制规则**：
- **禁止**在 PPT 页面中添加任何"来源：xxx"、"Source: xxx"、"数据来源：xxx"等来源/脚注行
- 此规则优先级高于任何 Visual Style 的特征描述（如 data-journalism 的"source lines"）
- 仅当用户在 prompt/确认中明确要求"加来源标注"时才可添加
- 不影响图表内数据标签的正常使用

**Why**：三个规则协同解决 AI 生成 PPT 的三个核心缺陷：(6a) 需精确平衡模板继承与布局自由度——继承太少（无 Logo/标题栏）导致裸白底、缺品牌标识；继承太多（整页照搬）导致全篇千篇一律。正确做法是框架继承（Logo+标题栏）+ 内容区自由设计。(6b) 底部空白浪费版面且缺乏信息闭环；(6c) 纯文字卡片排列缺乏视觉冲击力和叙事深度。三者分别从框架一致性、密度、丰富度三个维度提升输出质量。
**How to apply**：(6a) Strategist 写 spec_lock 时标记结构性页面 + 内容页头部框架，Agent prompt 明确列出 Logo 文件和坐标；(6b)(6c) Executor 逐页生成时自查。

### 6d. Logo 强制规则（2026-06-11 新增）

**教训**：陕西德联项目全部 24 页均无 Logo，根因是 Agent prompt 中完全没有提及模板 Logo 资源。

**强制规则**：
- 每个 Agent prompt 的约束区必须包含 Logo 放置指令，格式如下：
  ```
  ## Logo
  - 封面/结尾页：<image href="../templates/image3.png" x="997" y="41" width="258" height="56" preserveAspectRatio="none"/>
  - 目录/章节/内容页：<image href="../templates/image6.png" x="1058" y="31" width="203" height="38" preserveAspectRatio="none"/>
  ```
- spec_lock.md 的 `page_layouts` 中每一页对应的模板 SVG 已经包含了 Logo，Executor 生成时必须保留
- 内容页即使自由设计内容区，也必须保留右上角 Logo（image6.png）
- 质量检查阶段（svg_quality_checker）不检测 Logo 缺失（当前无此能力），由人工 / 记忆规则兜底

### 6f. 架构图所有层容器样式必须统一（2026-06-25 新增）

**教训**：融通 P08 五层架构中 L1-L4 有虚线边框容器 + 编号色块 + 层名 + 组件卡片，但 L5（应用层）只有裸 pill 标签，缺少虚线边框容器，与其他 4 层视觉不统一。这是 Agent 逐层生成时注意力集中在"内容是否正确"而忽略了视觉一致性的典型错误。

**强制规则**：
- 架构图（含模式 D 分层架构页）的**每一层**必须使用完全相同的容器样式：
  1. 虚线边框 `stroke-dasharray="6 4"`
  2. 浅色底色 `fill-opacity="0.15-0.25"`（颜色为该层主题色）
  3. 左侧编号色块（36-40px 宽 rx=8，内写层号数字，22px bold 白色）
  4. 层名标签（12-13px bold，放在容器内部左上角）
- 应用层（最顶层）即使内容为 pill/tag 而非组件卡片，容器样式也不能简化——pill 放在与下层卡片相同的 y 偏移位置
- 基础设施层（最底层）同样适用
- 生成后逐层对比验证：容器边框样式、底色 opacity、编号色块尺寸、组件卡片 → 全部一致
- **禁止**对顶层/底层使用简化或不同的容器样式

**Why**：架构图的每一层是平等的逻辑分层，视觉上必须体现对等性和一致性。简化某一层（即使是"轻量"的应用层）会破坏架构图的整体感和专业感。同时这属于 Agent 生成的典型盲区——Agent 擅长处理"每层应该有什么内容"但对"所有层看起来是否一致"缺乏全局感知。

**How to apply**：生成架构图前先读取 `layout-ref-architecture-layered.svg` 确认容器模板样式。生成后用肉眼或脚本逐层比对容器 rect 的属性（x/y/width/stroke/stroke-dasharray/fill-opacity）。
