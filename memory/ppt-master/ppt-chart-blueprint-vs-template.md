## 铁律（融通项目实测教训，2026-06-25）

**图表页生成，永远不要直接手绘 SVG。** 手绘坐标必然失调（卡片间距、badge 宽度、连接线弧度、阴影参数全凭感觉）。

正确做法只有两种，优先级递减：
1. **蓝本派生（首选）**：读模板 SVG → 提取精确坐标 → 只替换内容文本 + 色板 HEX + 字体 → 几何结构原封不动
2. **模板全量引用**：直接 `template:funnel_chart`，仅改数据占位符

**绝对禁止**：凭感觉手绘、自创 D3 风格几何图形、在没有 HTML 蓝本验证的情况下直接写 SVG

**v2.7.0+ 变更**：charts_index.json 已重构为结构命名（文件名描述视觉结构而非领域模型，如 `swot.svg`→`quadrant_text_bullets.svg`）。v2.10.0+ Slide library 暴露图表数据，Template-fill 路径可映射到 PPTX 原生图表。

## 两种图表生成方式

| | 蓝本派生 | 模板图表（charts_index.json） |
|------|---------|------------------------------|
| **做法** | HTML 蓝本作视觉参照 → Executor 在页面 SVG 中手工构建图表 | 从 71 个预置 SVG 模板（funnel_chart.svg 等）复制骨架 → 替换数据 |
| **来源** | 每次全新构建 | templates/charts/*.svg（74 个文件） |

## 逐项对比

| 维度 | 蓝本派生 | 模板图表 | 胜出 |
|------|---------|---------|------|
| **自定义度** | 无限。7→1 异形漏斗、非标层数架构图均可 | 受限于 71 种预定义结构。标准漏斗只支持 3-5 层 | 蓝本 |
| **视觉统一性** | 依赖 Executor 自律，不同批次间存在色差/字号漂移风险 | 模板已固化阴影参数、渐变、字号、间距，跨页绝对一致 | 模板 |
| **构建速度** | 每个图表从零手写，P04 漏斗约 80 行 SVG | 拷贝模板骨架→替换数据占位符，通常 20-30 行改动 | 模板 |
| **页面集成** | 图表天然嵌入页面内容区，与正文、闭合条无缝衔接 | 模板是独立全页设计，需裁切重构才能嵌入正文页 | 蓝本 |
| **内存规则合规** | 完全受控（无 emoji、无全幅 rect 等） | **7/71 个模板含 emoji**（💡🔍📊 等），违反 S2 | 蓝本 |
| **PPTX 可编辑性** | 所有元素是页面原生的 `<rect>` / `<text>` / `<path>` | 同样可编辑（模板也是 SVG 矢量） | 持平 |
| **可复用性** | 每次重建，无积累 | 一次学会模板结构，后续项目直接套用 | 模板 |
| **容错性** | 坐标计算错误直接导致错位（记忆规则 S4 反复触发） | 模板坐标经过验证，替换数据不发生结构漂移 | 模板 |
| **数据丰富度** | Executor 常简化辅助信息（缺标注/缺指标卡/缺数据来源行） | 模板自带 KPI 指标面板 + 洞察条 + 脚注行 | 模板 |

## 选用决策

```
图表是否高度定制化（异形结构/非标层数/特殊隐喻）？
  ├─ 是 → 蓝本派生（模板装不下）
  └─ 否 → 图表是否嵌入正文页（非独立图表页）？
           ├─ 是 → 蓝本派生（模板需大量裁切）
           └─ 否 → 图表是否是数据密集型（多标注/指标/洞察）？
                    ├─ 是 → 模板图表（骨架成熟，改数据即可）
                    └─ 否 → 蓝本派生（轻量级更快）
```

## 融合建议（两阶段混合）

当前实际执行的隐式混合策略可以显式化：

1. **结构型图表页**（架构图/框架图/对比表）→ **模板优先**：拷贝模板骨架，仅替换数据和配色。模板的阴影、标注面板、脚注等辅助元素全部保留，提升信息密度
2. **隐喻型图表页**（漏斗/金字塔/中心辐射）→ **蓝本派生**：模板结构通常无法匹配的定制隐喻（如 7→1 异形漏斗），由 Executor 手工构建
3. **原型内图表**（Dashboard 中的曲线/表格/KPI 卡）→ **蓝本派生**：天然嵌入页面，无需模板

**Why**：模板和蓝本不是互斥的。模板解决"标准结构的快速高质量产出"，蓝本解决"定制需求的灵活表达"。当前项目过于依赖蓝本（0 模板使用），未来应提升模板占比至 40-50%，减少重复手工劳动。
**How to apply**：Strategist 在 spec_lock.md §VII 中为每页标注图表来源：`template:funnel_chart` 或 `blueprint`。Executor 根据标注选择构建方式。
