## 核心结论

图表页生成质量排序：**蓝本派生（HTML→SVG）>> template-ref（5层提取）> 直接手绘**

模板参考的问题在于 Agent 即使读了模板 SVG，也只做"概念级参考"（知道是鱼骨图，但几何比例全丢）。蓝本派生迫使在 HTML 阶段就把坐标、间距、比例全部算清楚。

## 蓝本派生三步法

### Step 1: HTML 蓝本（定比例、定间距、定叙事）

用 HTML+CSS 做视觉蓝本，关键是：

- **先定叙事结构，再定布局**：不要上来就摆卡片。问自己"这页讲什么故事？"——P05 是"5 因→1 果"的因果链，P08 是"7 散→1 统"的对比叙事
- **CSS 写死宽高**：所有元素用 `position:absolute` + 精确 px 定位，不要依赖 flexbox/grid 的自动排列
- **验证间隙**：在 HTML 中目视检查每对相邻元素的水平和垂直 gap，确保 ≥20px
- **线必须连到框**：如果是 hub-spoke 或 convergence 图，在 HTML 中明确标记每个连接点的坐标

### Step 2: 坐标转写（精确计算，逐个验证）

从 HTML 蓝本中提取每个关键坐标，转写为 SVG：

```
强制验证项（每条线/每个框）：
1. 线起点 = 源卡片边缘 x 坐标
2. 线终点 = 目标卡片边缘 x 坐标
3. 相邻同层元素水平 gap = 右卡 left - 左卡 right（必须 ≥20px）
4. 上下层元素垂直 gap = 下层 top - 上层 bottom（必须 ≥15px）
5. 最右侧元素 right edge < 鱼头/大卡 left edge（必须 ≥100px 呼吸空间）
```

### Step 3: SVG 产出（严格用验证过的坐标）

HTML 蓝本的 px 值直接映射到 SVG 坐标，不做二次调整。

## 实战验证的两套布局模式

### 模式 1：鱼骨图（P05）— 统一角度 + 等距网格

**参照**：暂无满意的 SVG 参照（当前版本仍需迭代）。参数表见下，生成前优先使用 [[ppt-layout-rules]] 模式 D 的架构页参照。

| 参数 | 值 | 说明 |
|------|-----|------|
| 分支倾角 | **54.5°**（dx:dy ≈ 1:1.43） | 所有分支完全一致的斜率，视觉和谐 |
| 分支长度 | 80-100px（水平分量） | 控制在脊柱总长的 10-12% |
| 分支水平间距 | **230-245px 等距** | 相邻分支 title pill 的 gap 完全相等 |
| Pill 尺寸 | title pill 110×32, detail pill 95×22 | 比模板默认缩小 20%，避免拥挤 |
| 字号层级 | title 14px bold, detail 11px | 一页内不超过 3 级字号 |

**反模式**：分支角度不一致、pill 大小随意、间距靠"目测"

### 模式 2：汇入对比图（P08）— 边缘精确连线 + 散/统叙事

**参照**：暂无满意的 SVG 参照（当前版本仍需迭代）。核心参数见下表。

| 参数 | 值 | 说明 |
|------|-----|------|
| 左侧卡片排列 | **交替交错**（左 x=48 / 右 x=252） | 故意不对称，营造"散乱现状"感 |
| 连线 | 从卡片右边缘精确到统一卡左边缘 | 左卡 right=263/467 → 统一卡 left=670 |
| 统一卡 | 占右侧 45% 宽度，内含分区模块 | 用半透明 rect 在内部做功能分区 |
| 类别标注 | 上方 section label + 卡内左色条 | 两层标注确保信息不丢失 |

**反模式**：线没连到框边缘（最常见错误）、所有卡片整齐排列无对比感

## 与 template-ref 的适用场景对比

| 场景 | 推荐方法 | 原因 |
|------|---------|------|
| 定制隐喻图（鱼骨、漏斗、金字塔变体） | **蓝本派生** | 模板结构通常无法匹配定制的层数/分支数 |
| 对比/汇入叙事图 | **蓝本派生** | 需要精确的对比布局和边缘连线 |
| 标准数据图表（柱状图、折线图） | template | 信息结构标准化，模板骨架直接可用 |
| 标准架构图（4 层分层） | template | layered_architecture 模板直接匹配 |
| 原型内嵌图表 | 蓝本派生 | 天然嵌入页面，无模板可匹配 |

## Agent Prompt 传递要点

当使用蓝本派生法时，Agent prompt 必须包含：
1. **精确的坐标表**（不是"放在大概位置"）
2. **连接线的起点和终点坐标**（精确到 px）
3. **每个元素的宽高**（w=215, h=54，不是"大约 200 多"）
4. **间距验证规则**（gap 必须 ≥20px）

**Why**：蓝本派生法通过 HTML 蓝本阶段强制精确计算，从根本上消灭了"模板参考"中 Agent 凭感觉改参数导致的比例失调、元素重叠、线不连框三大顽疾。P05 经历 3 次重做（自由手绘→模板参考→蓝本派生），P08 经历 2 次重做，最终版本都通过 HTML 蓝本定比例→精确坐标转写→SVG 产出的三步法达到合格质量。
**How to apply**：给 Agent 的 prompt 中明确标注"蓝本派生"策略，并附上 HTML 蓝本或精确坐标表。不接受"改编版""非照抄模板"等模糊指令——要么给精确坐标，要么给 HTML 蓝本。
