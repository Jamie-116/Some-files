# 基础规格约束（硬性边界，必须严格执行）(Standard/Premium/Ultimate)
1. 比例与模板：16:9标准比例，指定模板：`templates/decks/hj_technology_white/`
 - **【核心强调】** 生成过程中必须深度调用且严格对应模板内置的原生页面组件：**Cover（独立封面）、TOC（目录）、Chapter（章节过渡）、Content（正文内容）、Ending（独立结尾）**。严禁自行拼凑或混淆这五类标准版式，确保层级完整、结构规范。
2. 篇幅控制：严格控制在 18-25 页之间（按内容单元计数，方案 3 双页原型的两页合并算 1 个内容单元，不因此挤占篇幅）。若单页内容过载，必须合理拆分为多页，拒绝文字堆砌。
3. 页码规则：全局**绝对不要**生成、显示或预留任何形式的页码（包括数字、总页数及"第X页"字样）。
4. page_layouts 克制原则：spec_lock 中的 page_layouts **仅标记结构性页面**（封面/TOC/章节过渡/结尾）。正文内容页**采用框架继承**——仅继承模板 Logo + 标题栏结构，内容区自由设计。**严禁**将 `03a_content_full` / `03b_content_two_col` 批量标记给所有正文页。

# 内容提炼与文本规范（硬性文本降噪）
1. 结论先行：每页正文页必须提炼出一个核心金句作为"单页结论型标题"（或加粗置顶的第一句话），严禁直接照搬文档原有的章节名作为唯一标题。v2.10.0+ 强调**每页一个核心信息点**——不要在一个页面塞多个论点。
2. 精简率与短语化：严格执行"Word搬家"降噪。源文档文本转化为 PPT 话术时，**字数压缩率必须达到 60% 以上**。严禁出现超过两行的完整长句，必须全面改写为"短语化、标签化"的要点。
3. 技术语调政企化：文本重构时，语调需从"底层开发说明书视角"切换为"高层价值与架构汇报视角"。多用高频政企技术词汇（如：打通、赋能、沉淀、统一感知、数智化转型），去除口语化和过程化大白话。
4. 非对称信息处理：必须识别文档中的因果、递进关系。严禁将"痛点（原因）"与"解决方案（结果）"用同等字数、同等字号扁平并列，必须通过字号大小、加粗或前置标签（如：【核心痛点】、【数智成效】）拉开内容的主次纵深。

# 视觉与版式规范
1. 色彩与风格：科技简洁风，以蓝白为主色，严格遵循B端企业级数智化转型VI规范。
 * **基底色**：纯白色 (#FFFFFF)，采用亮色模式 (light mode)。
 * **主色**：科技蓝 (#0082FF)，用于标题、关键词高亮、核心图表元素。
 * **辅助/强调色**：青色 (#28E6E6)、紫色 (#8254F0)、品红 (#C94CEB)，用于分层装饰、不同模块的区分、图表中的数据系列等。
 * **整体氛围**：基于以上配色，营造高级、统一、具有科技感的蓝白视觉氛围。
 * **注意**：以上为默认推荐色，Step 4 交互式确认页会展示 ≥3 个候选色板方案（含 HEX 自定义），用户确认后以 `result.json` 为准。
2. 留白与密度：追求"高信息密度"与"精细化排版"的平衡。最大化利用页面空间，但拒绝文字死板填满，底部严禁出现大片无意义的空白。
3. 视觉节奏感（拒绝千篇一律的卡片并列）(Standard/Premium/Ultimate)：
   - 严禁连续 3 页以上使用相同的排版布局（如连续使用四方块、三卡片）
   - (Premium/Ultimate) 收紧为：严禁连续 2 页使用相同布局，且全篇须覆盖 5 种以上不同布局模式
   - (Ultimate) 进一步收紧：全篇须覆盖 6 种以上不同布局模式，且同一章节内不得出现重复布局
 - 根据内容逻辑（如递进、对比、并列、中心扩散、金字塔），动态切换两栏、三栏、对角、流式等不同的原子组件布局。
4. 全页面禁止大段文字堆砌，正文段落超 3 行必须图表化拆分；采用图表 + 要点双栏排版，关键词高亮，功能页面搭配原生截图替代描述性文字，在保证高信息密度前提下精简冗余文案。
5. 视觉隐喻密度：
   - (Standard) 全篇 ≥2 页使用图表化隐喻元素（汇聚漏斗/金字塔/中心辐射/流程箭头链/对比天平/环形循环）
   - (Premium/Ultimate) 每个章节 ≥1 页使用图表化隐喻元素
   - (Ultimate) 隐喻类型不得跨章重复（如第 1 章用漏斗、第 2 章用金字塔、第 3 章用中心辐射……）
   - (Ultimate) 每个隐喻页必须搭配至少 1 张原型图，隐喻与原型形成"概念→落地"对照
   - 严禁全章纯文字卡片平铺 (Standard/Premium/Ultimate)
6. 图表模板覆盖率：技术架构、功能清单、对比分析、实施路线、KPI 总览等模块强制检索 `charts_index.json`。
   > 注意：v2.7.0+ charts_index.json 已重构为**结构命名**（如 `swot.svg` → `quadrant_text_bullets.svg`）。模板文件名描述视觉结构而非领域模型，匹配时以结构拟合度为依据。
   - (Standard) 全篇 ≥3 个不同 chart template（含结构型模板，非仅数据图表）
   - (Premium) 全篇 ≥4 个不同 chart template
   - (Ultimate) 全篇 ≥5 个不同 chart template，须跨 ≥3 个类别（数据类/结构类/流程类各至少 1 个）
7. 底部闭合原则：
   - (Standard) 正文页底部无 ≥80px 连续空白区
   - (Premium) ≥80% 正文页底部有主动闭合元素（总结条/数据标签行/关键结论短句）
   - (Ultimate) 100% 正文页底部有闭合元素，且至少出现 2 种不同形式（总结条、三标签行、数据胶囊、KPI 条等交替使用）
   - (Ultimate) 至少出现 3 种不同闭合形式，且闭合元素内必须包含数据量化信息（如"覆盖 X 个场景 / 提效 Y% / 上线 Z 天"）
   - 闭合条高度 30–55px，浅主色底，用于形成信息闭环 (Standard/Premium/Ultimate)

# 封面与结尾规范（v2.11.0 新增要求）

1. **封面 Hook + Composition**（v2.11.0 强制）：
   - 封面必须提交具体的 **hook + composition**，不再是通用标题页
   - hook 是对受众的"第一击"——一个数据、一个问题、一个对比，让受众在 3 秒内建立兴趣
   - composition 是封面的视觉构成策略——主视觉（图片/插画）+ 标题位置 + 日期/机构信息，三者构成完整的封面叙事
   - 封面生成两版：第一版使用模板默认背景（深蓝底配白色浅色系文字），第二版使用 `image_search.py` 搜索的背景图

2. **结尾 Final-Impression Takeaway**（v2.11.0 强制）：
   - 结尾页必须有明确的收束信息——一个金句总结、一个行动号召、或一组核心数据的浓缩回顾
   - 严禁空洞的"谢谢"页或纯装饰性结尾
   - 结尾页的语言调性应与封面 hook 形成呼应（开头抛问题 → 结尾给答案）

# 素材与可视化规范（解决AI感与纯文字问题）
1. 配图获取与质量控制（鼓励搜索，宁缺毋滥）：
 - **配图来源**：请复用源文档中的系统截图，同时**积极鼓励使用 `image_search.py` 搜索**与当前页面功能、业务场景高度适配的高质量真实图片或实景商务图。
   ```bash
   python3 ${SKILL_DIR}/scripts/image_search.py "search keywords" \
     --filename cover_bg.jpg \
     --provider pexels \
     --orientation landscape \
     -o <project_path>/images/
   ```
   可用 Provider：`pexels`（推荐，Key 已配置在 `~/.ppt-master/.env`）、`pixabay`、`openverse`、`wikimedia`。
 - **AI 图片生成**：v2.10.0+ 已切换为 OpenAI 兼容接口。若需要 AI 生成图片，使用 `image_gen.py --manifest` 模式（管道内强制 manifest 模式，禁止跳过）。
 - **底线原则**：配图必须与对应功能/场景一一对应。**宁可少做，绝不犯错**。若搜索不到高度相关的优质图片，宁可保持页面简洁留白，也绝不能插入毫无意义的装饰性网图、AI感明显的虚拟假人或违和的3D概念小人。
 - **配图占比**：配图页面占比： 30%-40%；图文交替排布，避免长段连续配图或纯文字页，文字、数据、流程页只用简易图标点缀，配图风格统一、疏密得当、留有留白。

2. 专业图表可视化：
 - 涉及技术架构、业务流程、功能对比、数据说明、部署拓扑等板块，强制使用内置的专业图表模板进行视觉设计。
 - 技术架构全景页：必须体现清晰的层级包含关系（如基础设施层、数据层、能力层、应用层），严禁做成扁平的"文字色块堆砌"，层级内各组件需规整对齐。
 - 其它页面尽量用高度提炼的图表、Icon组、时间轴替代大段文字。


3. 功能原型图生成（替代装饰性配图）(Premium/Ultimate)：
   - **定位**：功能讲解页用高保真 UI 原型图替代无信息量的装饰图或纯文字描述，展示"平台实际长什么样"。(Ultimate) 模式下原型图升格为**页面主体视觉元素**，文字退居为辅。
   - **核心方法论**：方案 1 采用 **"蓝本派生"** 工作流——先以技能（ui-ux-pro-max / frontend-design）产出 HTML 前端代码作为视觉蓝本，再将其视觉质量转译为等保真度的 SVG 矢量页面。HTML 蓝本仅作设计参照，不进入 PPTX 产物。
   - **生成模式（三选一，所有级别默认「蓝本派生」）**：

   | 方案 | 默认 | 一句话 |
   |------|------|--------|
   | **方案 1 — 蓝本派生** | ✅ 默认 | Executor 先用技能产出 HTML 高保真蓝本，再以蓝本为视觉参照，在 SVG 中用增强矢量元素（阴影滤镜/渐变色/状态徽章/交替行色/药丸按钮）绘制等视觉质量的 UI 原型。零外部依赖，PPTX 中全元素可编辑 |
   | **方案 2 — 技能混合** | 可选 | 调用 `ui-ux-pro-max` + `frontend-design` 混合生成高保真原型 PNG，嵌入 SVG。数据看板/Dashboard 类用 ui-ux-pro-max，表单/列表/CRUD 类用 frontend-design |
   | **方案 3 — 蓝本派生 + 技能混合双页** | 可选 | 方案 1 和方案 2 并行：每处需要原型的页面生成**两页**——一页蓝本派生版（HTML→SVG 转译，全元素可编辑）+ 一页技能混合版（PNG 嵌入，像素级还原）。两页内容相同、表现形式不同，给用户选择余地 |

   用户可输入 `原型方案2` / `原型方案3` 切换，未指定则默认方案 1（蓝本派生）。此选择与品质增强级别无关，Standard/Premium/Ultimate 均可自由选择任意原型方案。

   - **方案 3 双页规则**：
     - 两页为独立 SVG，内容逻辑一致但视觉形式不同
     - 蓝本派生版：HTML 蓝本→SVG 矢量转译，阴影/渐变/徽章/交替行色，全元素 PPTX 可编辑
     - 技能混合版：PNG 截图嵌入 + 标注框 + 文字说明，像素级还原真实 UI
     - 两页在 PPT 中连续排列（蓝本派生版在前），页码规则仍需遵守（两页均不显示页码）
     - **篇幅计数规则（关键）**：方案 3 的两页合并算 **1 个内容单元**，不计入 18-25 页篇幅上限。即：若一份 PPT 设计 20 个内容单元，其中 5 个采用方案 3，则实际 SVG 文件数 = 15 + 5×2 = 25 个，仍属于 18-25 页篇幅范围内。**不得**因为双页而压缩其他内容页来腾空间。

   - **生成时机（关键）**：在 Executor 生成对应功能页的**当时**即调用所选方案生成原型图，**不要**延迟到全部页面生成完后让用户单独操作。Executor 发现当前页需要原型图 → 立即生成 → 嵌入/绘制 → 继续下一页。此流程不可打断。
   - **生成数量**：
     - (Premium) 功能讲解页每 ≥3 页至少生成 1 张原型图
     - (Ultimate) 每个子系统 ≥1 张原型图，关键功能页（如智能调控主界面/总展示 Dashboard/报警中心）优先；**全功能页原型覆盖 ≥80%**：功能讲解页中至少 80% 的页面必须包含原型图；全篇原型组数 ≥ 功能页数 × 0.8
     - 方案 3 中：两页算 1 组，计数时按 1 处原型处理
   - **质量要求**：
     - 原型图必须与当前页描述的功能**一一对应**——生成"锅炉智能调控面板"就不是"通用仪表盘"
     - 配色方案沿用 spec_lock.md 的主色系，保持跨页风格统一
     - 严禁生成无信息量的纯装饰图或 AI 感明显的虚拟 3D 场景图
     - **宁少勿滥**：匹配不到合适功能界面的页宁可留白不用图（(Ultimate) 模式下仍需满足 80% 覆盖率，可用关联功能界面替代，不强制一一对应但语义必须关联）

# 图表生成策略（解决信息架构单薄问题）(Standard/Premium/Ultimate)

## 核心原则

> **模板出结构，蓝本出风格，Executor 出内容。**

模板图表（charts_index.json，v2.7.0+ 已重构为**结构命名**——文件名描述视觉结构而非领域模型）定义"信息应该怎样组织"——分层/标注/KPI/洞察/脚注。蓝本定义"视觉应该长什么样"。两者交集 + Executor 填入页面数据 = 信息厚度与视觉质量兼得的图表。

v2.10.0+ Slide library 暴露图表数据，若走 Template-fill 直通路径可将 Markdown 表格数据直接映射到 PPTX 原生图表。本提示词默认使用 SVG 管线（不对 PPTX 直接编辑）。

## 图表选型决策链

每一页需要图表化的内容，按以下链路逐级判定：

```
内容需要图表化？
    ├─ 否 → 普通内容页
    └─ 是 → charts_index.json 中存在匹配结构？
               ├─ 完全匹配 → 【全量模板】拷贝模板骨架，改数据 + 调色系
               ├─ 近似匹配 → 【骨架参考】提取模板 5 层结构，蓝本视觉重绘，填入页面数据
               └─ 无匹配   → 【纯蓝本派生】HTML 蓝本参照 + 手工构建（含必建结构层）
```

**完全匹配**：模板的图表结构和页面内容一一对应（如标准漏斗、四层架构、中心辐射）。

**近似匹配**：模板结构方向正确但细节有偏差（如异形漏斗 7→1、非标层数架构）。此时不照搬模板形状，但**必须提取模板的信息架构层**（标注/指标/洞察/脚注）。

**无匹配**：模板库中不存在可参考结构（如原型页内嵌 Dashboard 曲线/表格/KPI 卡），纯蓝本派生。

## 模板 5 层结构提取（Executor 操作规范）

从模板 SVG 中提取以下 5 层（不照搬全页，只抄骨架）：

| 层序 | 名称 | 说明 | 强制 |
|------|------|------|------|
| L1 | **图表主体** | 核心可视化元素（漏斗/层级/辐射线/时间轴） | ✅ |
| L2 | **标注层** | 数据标签、百分比、箭头、对比数值 | ✅ |
| L3 | **指标面板** | KPI 侧栏卡片（色条 + 数值 + 描述） | ✅ |
| L4 | **洞察条** | 底部浅色条，含关键洞察短句 + 行动建议 | ✅ |
| L5 | **来源脚注** | 灰色小字数据来源/统计周期 | 可选 |

提取后逐层用**蓝本视觉参数**重绘（主色 → #0082FF、阴影 stdDeviation → 4、按钮 rx → 19、删除 emoji、字体 → Microsoft YaHei）。近似匹配时 L1 图表主体由 Executor 按实际内容重建，L2-L5 照常提取。

# 并行生成策略（提速）⚠️ 已知与 SKILL.md §6/7/8 冲突，但经实际验证有效，优先执行本规则

`spec_lock.md` 已包含全量设计约束（配色、图标库、页面结构、内容大纲、mode、visual_style），因此内容页之间互相独立，必须并行生成。

## 三阶段流水线

```
阶段 1（串行）          阶段 2（并行）                       阶段 3（串行）
Strategist 产出      →  N 个 Executor 并行              →  校验 + PPTX 转换
design_spec.md          各领 3–5 页独立生成 SVG
spec_lock.md            统一读 spec_lock.md 为约束源
```

## 阶段 2 并行规则

1. **分页**：按总页数 18–25 页，拆为 4–6 个并行批次，每个批次负责 3–5 页
2. **约束源**：所有并行 Executor 统一读 `spec_lock.md`（含 page_layouts、icons、色调、mode、visual_style），不得各自发挥
3. **独立页**：封面(P01)、目录(P02)、结尾(最后 2 页) 可与内容页并行生成——它们都在 spec_lock 中有明确定义
4. **有依赖的页**：
   - TOC 页的章节标题来自 spec_lock §IX Content Outline，不依赖其他页 → 可并行
   - Chapter 过渡页与内容页相互独立 → 可并行
   - 真正串行依赖：无。spec_lock 已将全局信息收敛完毕
5. **原型图页**（Premium/Ultimate 方案 2/3）：包含原型图的页与其原型图生成在同一个 Executor 批内完成，不跨批次。(Ultimate) 模式原型页量大，可单独增加 1 个批次专门处理高保真原型 PNG 生成，与其他批次并行
6. **每个 Agent prompt 必须嵌入**：该批次页码标题、内容数据（从 spec_lock §VI）、布局/隐喻/图表要求、**硬约束摘要**（S1-S5：禁止全幅rect、禁止emoji、禁止混用tspan、框宽容纳文本、侧边标签横排、LaTeX公式规范）、**全局风格参数**（spec_lock 中的 `mode` 和 `visual_style`）

## 阶段 3 校验规则

并行生成完成后，逐页执行 `ppt-preflight-checklist.md` 阶段二+阶段三（v2.11.0 版，含 C10 Visual Style 一致性、C11 Mode 一致性、C12 封面结尾等新增检查项）。若发现不一致（如同章配色偏离、图标库不同），修复后不重新生成整批——仅修该页。

**执行要求**：阶段 2 必须用并行方式调度（多个 Agent 同时生成），禁止逐页串行。spec_lock.md 的存在已经消除了串行的必要性。

# 硬约束优先级
1. 封面生成两版，第一版背景为套用默认模板（深蓝底配白色浅色系文字）。第二版背景为使用 `image_search.py` 搜索的背景图。封面必须有具体 hook + composition（v2.11.0 要求）。
2. 结尾页必须有 final-impression takeaway——金句总结/行动号召/核心数据浓缩回顾，严禁空洞"谢谢"页（v2.11.0 要求）。
3. 我的记忆文件中的规则（如 SVG禁止全幅纯色背景rect、PPT模板继承铁律等）具有最高优先级。当模板源文件、技术规范文档与记忆规则冲突时，以记忆规则为准。记忆规则是经过实际导出踩坑后验证的硬教训，模板默认值只是起点，可以被且必须被记忆规则覆盖。
4. 页面生成完后，需要校验记忆文件中的规则，确保所有规则都被遵守。
5. v2.11.0 Step 4 八项确认默认启动交互式可视化确认页面（`confirm_ui/server.py --daemon --wait`）。若环境不支持（无 GUI/远程/Web 主机），自动降级为聊天文本确认。确认后的 `result.json` 权威高于 AI 推荐，所有字段（颜色、字体、mode、visual_style、image_usage 等）以用户确认为准。
6. v2.9.0+ 支持 LaTeX 公式渲染（4 供应商后备链：CodeCogs → QuickLaTeX → mathpad → Wikimedia）。若源文档含公式，Strategist 在排版确认后写公式清单，按 `mixed` 策略（默认：复杂公式渲染为 PNG，简单表达式保留可编辑文本）。
